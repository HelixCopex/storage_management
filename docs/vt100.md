这个头文件实际上是一个**VT100/ANSI终端颜色与格式控制库**，作用是：

> **将带有颜色、背景色、格式（粗体、下划线等）的文本，在“结构化数据”和“ANSI转义序列字符串”之间进行双向转换。**

简单说：

* `编码（Encode）`：结构体 → ANSI颜色字符串
* `解码（Decode）`：ANSI颜色字符串 → 结构体链表

适用于：

* Linux终端
* xterm
* SSH终端
* Windows Terminal
* 串口调试终端
* TUI（Terminal UI）程序

例如：

```c
printf("\033[31mHello\033[0m\n");
```

显示红色：

```
Hello
```

而这个库就是专门处理这种：

```text
\033[31m
\033[1m
\033[38;5;196m
\033[38;2;255;0;0m
```

ANSI SGR（Select Graphic Rendition）控制序列的。

---

# 一、核心数据结构

## 1. vt100_color_t

```c
struct vt100_color_t {
  enum {
    palette_8,
    palette_8_bright,
    palette_256,
    truecolor
  } type;

  uint32_t value;
};
```

表示一种颜色。

---

### palette_8

标准8色：

```text
0 黑
1 红
2 绿
3 黄
4 蓝
5 紫
6 青
7 白
```

对应：

```text
30~37
40~47
```

例如：

```c
{palette_8, 1}
```

↓

```text
ESC[31m
```

红色前景

---

### palette_8_bright

高亮8色：

```text
90~97
100~107
```

例如：

```c
{palette_8_bright,1}
```

↓

```text
ESC[91m
```

亮红

---

### palette_256

256色模式

例如：

```c
{palette_256,196}
```

↓

```text
ESC[38;5;196m
```

亮红

---

### truecolor

24位真彩色

例如：

```c
{truecolor,0xFF0000}
```

↓

```text
ESC[38;2;255;0;0m
```

RGB红色

---

# 2. vt100_node_t

```c
struct vt100_node_t {
  char *str;
  int len;

  struct vt100_color_t fg;
  struct vt100_color_t bg;

  uint8_t mode;

  struct vt100_node_t *next;
};
```

这是整个库最重要的数据结构。

表示：

```text
一段文字
+
颜色属性
+
背景属性
+
格式属性
```

例如：

```c
{
    "Hello",
    红色,
    黑底,
    粗体
}
```

---

多个节点形成链表：

```text
[Hello]
   ↓
[World]
   ↓
[!]
```

每个节点都能拥有不同颜色。

例如：

```text
Hello -> 红色
World -> 绿色
!     -> 蓝色
```

---

# 二、vt100_sgr()

## 功能

根据节点生成 ANSI 转义序列。

函数：

```c
char *vt100_sgr(
    struct vt100_node_t *node,
    struct vt100_node_t *prev
)
```

例如：

```c
node->fg = 红色
```

生成：

```text
ESC[31m
```

---

如果：

```c
node->fg = truecolor
node->value = 0xFF0000
```

生成：

```text
ESC[38;2;255;0;0m
```

---

## prev参数作用

优化输出。

例如：

```text
红色 Hello
红色 World
```

第二段无需再次输出：

```text
ESC[31m
```

因为颜色没变。

所以：

```c
prev != NULL
```

时会比较：

```c
prev->fg
prev->bg
prev->mode
```

只输出发生变化的部分。

---

# 三、vt100_encode()

## 功能

链表 → ANSI字符串

```c
char *vt100_encode(
    struct vt100_node_t *node
)
```

例如：

链表：

```text
节点1:
  Hello
  红色

节点2:
  World
  绿色
```

---

编码后：

```text
ESC[31mHello
ESC[32mWorld
```

实际字符串：

```c
"\033[31mHello\033[32mWorld"
```

---

流程：

```text
遍历链表
   ↓
生成SGR
   ↓
拼接文本
   ↓
返回完整字符串
```

---

# 四、vt100_parse()

## 功能

解析一个 ANSI SGR 序列。

例如：

```text
ESC[31m
```

解析为：

```c
fg.type  = palette_8
fg.value = 1
```

---

例如：

```text
ESC[38;5;196m
```

解析为：

```c
fg.type  = palette_256
fg.value = 196
```

---

例如：

```text
ESC[38;2;255;0;0m
```

解析为：

```c
fg.type = truecolor
fg.value = 0xFF0000
```

---

## 状态机设计

变量：

```c
int state = 0;
```

用于解析：

```text
38;5;196
```

或者：

```text
48;2;255;0;0
```

---

当读到：

```text
38
```

表示：

```text
前景色扩展模式
```

于是：

```c
state = 38;
```

---

接下来看到：

```text
5
```

说明：

```text
256色
```

再读取：

```text
196
```

最终得到：

```c
palette_256
```

---

# 五、vt100_decode()

这是整个库最强大的部分。

## 功能

ANSI字符串 → 节点链表

例如：

```text
ESC[31mHello
ESC[32mWorld
```

解析后：

```text
Node1:
  Hello
  红色

Node2:
  World
  绿色
```

---

流程：

```text
扫描字符串
      ↓
发现ESC
      ↓
调用vt100_parse
      ↓
记录当前颜色状态
      ↓
创建新节点
      ↓
继续扫描
```

---

例如：

```text
Hello
ESC[31m
World
ESC[32m
!!!
```

得到：

```text
Node0:
 Hello

Node1:
 World
 红色

Node2:
 !!!
 绿色
```

---

# 六、全局状态机制

```c
global_fg
global_bg
global_mode
```

这是一个状态机。

因为VT100协议本身就是：

```text
状态保持式
```

例如：

```text
ESC[31m
Hello
World
ABC
```

虽然只有一次：

```text
31m
```

但后面全部是红色。

---

因此库维护：

```c
global_fg
```

表示：

```text
当前终端颜色状态
```

解析下一个节点时继承。

---

# 七、mode字段

```c
uint8_t mode;
```

每个位表示一种格式。

```text
bit0 粗体
bit1 暗淡
bit2 斜体
bit3 下划线
bit4 闪烁
bit5 快闪
bit6 反色
bit7 隐藏
```

---

例如：

```c
mode = 0b00001001
```

表示：

```text
粗体
+
下划线
```

---

生成：

```text
ESC[1m
ESC[4m
```

# 九、这个库的设计特点

优点：

✅ 同时支持

* 8色
* 亮色
* 256色
* TrueColor（24位）

✅ 支持双向转换

```text
结构体 ↔ ANSI字符串
```

✅ 使用链表表示富文本

适合做：

* TUI框架
* 终端渲染器
* ANSI日志解析器

---

缺点：

1. 使用大量全局变量

```c
global_fg
global_bg
global_mode
```

线程不安全。

---

2. 内存管理比较粗糙

例如：

```c
malloc(128)
```

固定大小缓冲区存在理论溢出风险。

---

3. 不支持完整VT100协议

只支持：

```text
CSI ... m
```

即 SGR 图形属性。

不支持：

```text
ESC[H   光标定位
ESC[J   清屏
ESC[K   清行
ESC[s   保存光标
ESC[u   恢复光标
```

---

因此可以把这个库理解为：

> 一个专门处理 ANSI/VT100 颜色与文字格式（SGR）的轻量级“富文本解析器”，能够在终端转义序列与结构化文本节点链表之间进行双向转换。
